# 分支模板

新建分支时复制下面三份到 `branches/<分支名>/`：`SKILL.md`、`exam.md`、`sources.md`。分支名用 `know-<领域>`（英文小写短横线），方便一眼认出是知识树分支而不是生产 skill。先写主干和领域地图，再收细节。

`SKILL.md`：

```markdown
---
name: know-<领域>
description: <领域>的专家底子。Park 说「<大白话触发 1>」「<触发 2>」「<触发 3>」时，在动手（或调用 <相关生产 skill>）之前先用它：把需求拆成几类让他挑，只问一轮关键问题。
---

# <领域>：做之前该懂什么

## 怎么用这份
1. Park 不是这个领域的专家：别等他给清楚的指令和行话。
2. 需求含糊 → 用「领域地图」让他挑（每类配样例），用「先问的问题」问一轮（≤3 个，带选项和推荐默认）；他说「你定」就用默认。
3. 需求已经清楚、或做错代价很低 → 直接做，做完说用了哪些默认。
4. 动手交给 <生产 skill>，做完按「好坏标准」自检；被 Park 否了就记进「翻车账」。
```
