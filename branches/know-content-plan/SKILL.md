# 排一批内容：做之前该懂什么

## 怎么用这份
1. 给 Park 自己排：定位已经有了（读 PARK-OS 和他的账号定位），不再问他「给谁看」；选题是他的，我只从他的原始输出和读者问题里提候选让他挑，不替他编题。
2. 给咨询客户或新号排：客户通常说不清定位，用「先问的问题」问一轮，第 1 题我先替他填一版定位句让他改。
3. 交付一张批次表（见 `references/batch-table.md`），每篇一行；发完一组按「复盘」那段看数，再定下一组。被否了记进「翻车账」。

## 主干（底层原理，细节都挂在这上面）
1. **定位是选题的边界**：「帮【什么阶段的人】在【什么场景】解决【一个问题】，用【我拿得出的材料】讲」。写不出这句，就排不出选题。
2. **选题来自读者在问什么，不是我能讲什么**：搜索建议、同行评论里的「那我这种情况怎么办」、自己反复卡住的步骤；连读者的情境一起记。
3. **第一批是一组能比较的试验**：混几种形式、围绕同一批人的几个相邻问题，发完才看得出哪类有人关心、哪种讲法自己做得出。
4. **材料决定能不能做**：没材料的题先放备选；没结果写过程，没做过不写成亲历，拆别人的案例要标出处、分清观察和推测。
5. **按组复盘，一次只改一个变量**：每 3–4 篇停一次，同口径比数，把读者追问变成下一篇。

## 领域地图（「排一批内容」其实分这几类）
| 类 | 一句话 | 样例 |
| --- | --- | --- |
| 新号第一批 | 从定位句出发排 8–12 篇，混形式 | 小红书新号头两周 |
| 换平台 | 同一批人换个地方，场景和形式要跟平台换 | 抖音口播搬到小红书图文 |
| 换方向 | 旧内容不再服务目标读者，重写定位句再排 | 从泛 AI 工具转到「一人公司」 |
| 下一批 | 上一批发完，按反馈定下一组 | 评论都在追问某一步 → 做演示 |
| 系列 | 一个大题拆成连续几集 | 「一人自媒体究竟怎么做」 |

内容形式（一批里混着用，起点配比 方法 3 / 案例 4 / 过程 3 / 模板 2）：
- 方法：把步骤讲清楚
- 案例拆解：步骤落在具体材料上长什么样
- 过程记录：保留选择和修改的理由（没结果也能写）
- 清单模板：替读者省掉整理的时间

## 先问的问题（一轮问完；给 Park 自己排时只问 2、3）
1. 定位句对吗？（我先按已知信息填一版：帮【…】在【…】解决【…】，用【…】讲；推荐：人群越窄越好）
2. 手里有哪些材料？ 选项：真实操作截图/录屏 / 过程记录 / 客户案例（能公开的）/ 公开的同行案例 / 只有观点（推荐：有截图和过程的题先排）
3. 多久发一篇、先排几篇？（推荐：先排一组 4 篇，发完复盘再排下一组）

## 好坏标准
- 过：每篇都在帮同一类人；每篇有一个写得完的具体问题（「只有产品照片，第一批能发什么」，不是「小红书怎么运营」）；每篇写了所需材料，而且拿得到。
- 过：选题都能放进 2–3 个长期栏目；放不进的单独存着。
- 不过：自我介绍 + 追热点 + 工具合集各来一篇，主页看不出在帮谁；几篇换了标题正文差不多（合并）；为凑形式比例编经历、编数据。

## 坑
- 先发自我介绍、再跟热点、再做合集 → 每篇都说得过去但放一起没方向，十篇后分不清是方向错还是没讲明白。（主干 3）
- 只记「求教程」三个字 → 要连读者的情况一起记，才知道教程讲到哪步。（主干 2）
- 换赛道只换关键词 → 读者场景和证据要一起换。（主干 1）
- 刚发两小时和发了一周的笔记直接比总收藏 → 同观察时长、同比例口径（如收藏 ÷ 阅读）。（主干 5）
- 标题、封面、受众、篇幅一起换 → 数据变了也不知道该保留什么。（主干 5）
- 阅读样本少就判定位死刑 → 先补做相近问题。（主干 5）

## 复盘（每组发完看这几条）
- 有人追问某一步 → 下一篇专门演示那一步。
- 收藏多、评论少 → 偏查阅型，不必硬加提问，看来的是不是目标读者。
- 标题引来的人不对 → 标题太宽，或承诺了正文没解决的事。
- 记录：标题、形式、发布时间、制作耗时、后台实际指标；没有的数据留空，不猜。
- 一批结束要答得出：哪些问题有人继续问、哪些内容能持续做、下一批有哪几个具体题。

## 词表（行话 ↔ 大白话）
- 定位 = 我帮谁、在什么时候、解决什么
- 栏目 / 内容支柱 = 账号长期反复讲的 2–3 个主题
- 对标 = 值得学的同类账号
- 垂直 = 一直帮同一批人，不等于连发十篇同一个问题
