# 产品与服务定价：做之前该懂什么

## 怎么用这份
1. 先认领域：为自己的产品或服务定价、设计收费档位、判断是否涨价，进入本领域；其他需求正常处理。
2. Park 不必懂定价行话。需求含糊时，用领域地图的具体例子让他挑，一轮问完下面至多三问；他说「你定」或没回答的，用推荐默认，缺的数据写成待验证假设。
3. 已有事实直接提取；需求清楚或试错代价低就直接做，说明采用的默认。
4. 交给 monetization-strategy、dbs-diagnosis 或直接形成报价比较方案，按好坏标准自检；被否了记翻车账。方案价与现行价分列，对外报价和承诺以 Park 已给定的为准。

## 主干
1. **从买家的价值和预算定边界**：先确认谁付款、为什么要买、可用预算与替代方案，别拿自己的消费习惯判断客户买不起；公司营收或个人净资产都不等于本次预算。
2. **高价档要买到不同的交付**：让客户更快拿结果、更少自己动手，或减少可控制的交付不确定性；每项差异都写成具体服务与验收，不能只有价格和名字不同。
3. **看实际留下的钱和占掉的产能**：各档按同一周期比较成交人数、实收、获客、交付、售后、退款及新增固定成本；同时看每单贡献、每小时贡献和总贡献。利润率高或成交率高，都不足以证明值得做。
4. **交付方式决定适合的量价组合**：人工服务产能有限时，先验证少量高价值交付；低价大量模式先证明获客和自动交付能承受。新档一次验证一档，现有入口不因读到高价案例就撤掉。
5. **涨价是要验证的假设**：先筛同类合格买家，再比较不同报价的成交与贡献；拒绝多先查预算、价值差异和表达，需求持续超过产能才是试探涨价的信号。别把作者的成交率、倍数或财富分布当本业务定律。

## 领域地图
| 类 | 先解决什么 | 样例 |
| --- | --- | --- |
| 首次报价 | 谁买、买到什么、成本底线 | 给老板装一套团队每天用的系统，先划清交付和验收 |
| 新增高价档 | 谁愿为额外省时省事付钱 | 标准工具之外，加部署、迁移和培训；逐项算新增成本 |
| 涨价与产能 | 接单上限与利润是否匹配 | 档期排满，比较涨价后少接几单能否增加总贡献 |
| 低价大量 | 能否低成本服务足够多人 | 自助订阅先测支持工时和获客成本，不能靠低价堆人工 |
| 拒绝与低利润 | 是客户不对、交付不清还是成本过高 | 同类合格客户仍不买，查价值和替代方案再改价 |

## 先问的问题（一轮问完）
1. 这次卖给谁，谁付款、预算有什么依据？选项：个人自费 / 小团队或老板 / 大企业采购 / 还没确定（推荐：沿用已有付费客户中需求匹配、预算有依据的一类；无材料先标假设）。
2. 客户要自己做到哪一步，我们替他做什么？选项：自助工具或资料 / 一起做 / 代做并交付 / 优先交付与持续支持（推荐：先保留已验证交付，只为高价档增加一个可验收的省时省事差异）。
3. 这次改价要解决什么，手里有哪些数？选项：首次报价 / 加高价档 / 档期满想涨价 / 客户嫌贵或忙却不赚钱（推荐：只试一个档，沿用现有实收、成本、工时和同类买家成交数；缺数先做小批验证）。

## 好坏标准
- 过：每档都有具体买家、付款依据、交付差异、范围和验收；新增高价档能说明客户少做了什么或更快得到什么。
- 过：人数不跨档重复计算，月费和一次性费用换到同一周期；新增服务的售前、交付、售后与固定投入都有成本或待测项；每单、每小时和总贡献共同支持选择。
- 过：一次只验证一个新档；写清同类合格买家、比较基线、观察周期及继续或调整的条件，未验证数字明确标假设。
- 不过：只因朋友嫌贵就降价；只看成交率；直接按某个倍数涨价；高价档堆更多人工却不算工时；把未验证结果写成保证。

## 坑
- 客户说贵就立刻降价 → 先查预算、预期结果和可比替代，再决定改人群、交付还是价格。（主干 1、5）
- 把相同交付改个名字加价 → 为高价客户增加可观察的速度、省事或交付确定性，并算成本。（主干 2、3）
- 自动化尚未跑通却追求低价海量 → 先用实际交付和售后工时判断能否承受该规模。（主干 4）
- 把「更确定」写成无条件收益保证 → 只承诺自己能控制的交付与验收，结果假设单列。（主干 2）

## 词表
- 高价档 / upsell = 同一客户愿意为更省事的交付多花钱。
- 合格买家 = 需求匹配、有本次预算、能推动付款的人。
- 每单贡献 = 本单实收减去随本单增加的成本；总贡献还要扣新增固定投入。
- 价格锚点 = 一个真实可交付的高价选择，供客户比较价值。
