# 做 3D 游戏：做之前该懂什么

## 怎么用这份
1. Park 不是游戏开发者：他会说「做个像《小王子》那样的星球世界」。我负责把它拆成场景、角色、玩法三张清单。
2. 需求含糊 → 用「领域地图」让他挑，用「先问的问题」问一轮（≤3 个，带推荐默认）；他说「你定」就用默认。
3. 动手前先给他看一页需求（场景、角色、玩家能做什么、一条故事线）和一张场景参考图，确认后再建模；被 Park 否了就记进「翻车账」。

## 主干（底层原理，细节都挂在这上面）
1. **先锁一张参考图，再做一切**：画风、配色、物体位置都由第一张满意的效果图定，其他角度围绕它补。没有参考图就建模，比例和质感一定飘。
2. **生成什么、搭什么要先分清**：造型复杂、要精细的道具和角色用 3D 生成；地面、墙、简单几何体直接在建模软件/引擎里搭。拆分结果标在图上给人确认。
3. **流水线有顺序，前一步不过不进下一步**：网格不对不上贴图，骨骼没对齐不接动作，基础动作不对不做复杂交互。
4. **检查靠多机位对照参考图**：正面、侧面、俯视截图和参考图逐项比；最好由另一个独立的审查者盲审，不让建模的自己说好。
5. **人和东西接触的动作最难**：动作库里通常没有现成的，选一个接近的基础动作再细调，专门查手有没有握住、有没有穿模、东西有没有悬空。

## 领域地图（「做个 3D 游戏」其实分这几类）
| 类 | 一句话 | 样例 |
| --- | --- | --- |
| 漫游探索 | 玩家在场景里走、看、点东西触发剧情，没有输赢 | 《小王子》星球之旅；最容易做成 |
| 互动叙事 | 跟着一条故事线推进，选择改变走向 | 走到角色面前对话、解锁下一站 |
| 小玩法游戏 | 有一个核心操作和目标（收集、躲避、解谜） | 收齐 5 颗星离开星球 |
| 3D 展示 | 不玩，只转着看一个场景/角色/产品 | 个人 IP 手办 3D 展台 |

## 先问的问题（一轮问完）
1. 玩家进去以后主要做什么？ 选项：随便逛 / 跟着故事走 / 完成一个目标（推荐：随便逛 + 几个可点的彩蛋，最快做出来）
2. 几个场景、几个会动的角色？（推荐：1 个场景、1 个主角，先跑通再加）
3. 画风参照什么？ 给 3–4 张参考图让他挑（插画风 / 低多边形 / 手办潮玩 / 写实），不让他描述。

## 好坏标准
- 过：场景从各个机位看都和参考图一致；角色四个视角细节统一；基础动作（抬手、弯腿、转身）没有明显变形、拉扯、穿模。
- 过：每个复杂交互（拿、提、推）手和道具接触稳定，没有脱手或悬空。
- 不过：没有参考图就开始建模；网格乱就上贴图；动作直接套用不检查骨骼是否匹配；只看一个角度就说完成。

## 坑
- 一开始就做多个场景、多个角色 → 先 1 个场景 1 个主角跑通整条流水线。（主干 3）
- 角色多视图细节不统一 → 生成 3D 时会拼出怪物；先把四视图统一再生成。（主干 1）
- 让做的人自己验收 → 总说像；另派审查者多机位对照参考图找差异。（主干 4）
- 动作库没有完全合适的动作 → 不要硬套，选近似的再细调。（主干 5）

## 词表（行话 ↔ 大白话）
- PRD = 一页需求：有哪些场景、角色、故事、玩家能做什么
- 3D 资产 = 场景里的一个个物件或角色模型
- 白模 / 网格 = 还没上颜色的模型骨架外形；贴图 = 给模型上颜色和质感
- 拓扑 / 面数 = 模型由多少块小面组成，越整齐越好改、越好动
- T-pose 四视图 = 角色张开双臂站直，前后左右四张图
- 绑骨 / 蒙皮 = 给模型装骨架、让皮跟着骨头动
- IK = 拖手的位置让整条胳膊自动跟着摆
- 引擎 = 把场景、角色、操作打包成能玩的游戏的软件（如 Unity）
- 穿模 = 两个东西互相穿过去了
